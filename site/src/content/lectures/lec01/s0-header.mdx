This is day 2 of week 1. It finishes the course framework that day 1 started, and every part of it is worked through on one running case, Medium, with attention to how things are actually implemented and what they buy you in performance. [[L-0001]]

The class went through caching at different levels, then scaling, delegation, concurrency and communication, in that order, and this page follows it. Delegation before concurrency works well here: the counter that delegation builds is exactly the thing concurrency breaks. [[L-0007]]

Concurrency gets only a short taste here. Week 2, day 1 goes deep on how concurrency in a database falls apart, with practical examples. The whole course runs 8 weeks, 16 sessions, kept focused on engineering. Security is not part of it: it is not high-level architecture, and the course website lists the exact topics the course does cover. [[L-0008 L-0005 L-0351]]

### Medium so far

Here is Medium’s picture as this class starts. A reader’s browser sends a request to an API server, the API server reads the story from one database, and the answer goes back the same way. There are two API servers, and next to the database sits one shared cache, a Redis instance that every API server can call. [[L-0013]]

That picture works until a story goes viral. This page grows it, one box at a time. Each section starts from something Medium is struggling with right now and ends with a rule you can take to any other system.
