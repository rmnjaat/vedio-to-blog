The board’s agenda for this session had four items: how to approach designing a distributed system, designing a load balancer, remote and distributed locks, and synchronizing consumers. The first one is about approach, not theory, and there is no secret sauce to it. [[L-0004]] The load balancer gets a very realistic design plus a short walk through the source code of a tiny load balancer written for the class, to see the core logic rather than just draw boxes; that code is in no way production-ready. [[L-0006]] Remote and distributed locks came after the break, and this page keeps the class’s order. [[L-0009]]

**How to study this page.** Real design discussions run three or four hours straight, and covering a system has to happen in one go, because re-setting the context costs about 20 minutes; so read a chapter in one sitting. ### The load balancer so far

So far in this course the load balancer has only been a box. In Lecture 2 Medium’s API servers scaled out behind one. The pieces this lecture builds it from are already here. Lecture 1’s online indicator turned heartbeats into a failure detector, and chapter 4 turns them into health checks. [[L-0165 L-0350]] Lecture 3 locked rows inside one database for an airline check-in, and chapters 6 and 7 do the same across machines. [[L-0014]] Lecture 4 pushed Slack’s membership changes over Pub/Sub, and chapter 4 pushes configuration the same way. [[L-0177]]
