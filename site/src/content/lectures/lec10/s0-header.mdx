This is day 2 of week 5, and it continues the week’s subject, storage engines. The agenda is two problem statements: a word dictionary without any database, and a superfast key-value store. Both were chosen to build foundational blocks, for designing interesting new systems and for getting the most out of the ones that already exist. [[L-0001]]

Neither is a toy. Both systems are actively used in production, to a huge extent; this is not something that is just theoretical. [[L-0002]] The problem statement was put together on purpose to touch a lot of the critical building blocks used day in and day out in the real world: file formats, indexes, object storage, rollouts, append-only logs and checksums all turn up before the end. [[L-0008]]

**How this page is built.** Each engine is designed from nothing, one step at a time, and named only at the end, as in class. The class’s question-and-answer time is folded into the chapter it answers.

</MarginNote>

### Our storage so far

Yesterday’s session built a cache like Redis: one hash table in memory, every byte counted, then split across many nodes with a ring to find each key, and an append-only file to come back after a restart. Earlier still, Lecture 3 built a key-value store on top of MySQL, where a delete was an update with a magic value and a cleanup job removed rows in batches.
