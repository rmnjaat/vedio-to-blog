# Direction B: Whiteboard Notebook

Sample: `index.html` (one self-contained file; only Google Fonts are external). Section shown: Lecture 01, §2.4 "Scaling the database". Content comes from ledger items K1-073..K1-131 (part 1) and K3-024..K3-095 (part 3). The one outside fact is quoted from PostgreSQL docs §26.2.5 (https://www.postgresql.org/docs/current/warm-standby.html#STREAMING-REPLICATION), checked 2026-10-11.

The figures were generated by a small deterministic script (seeded wobble, single strokes, no hachure). It is not shipped with the sample. In the real build, figures would be authored once per glyph and reused, or produced by the same generator at build time.

Theme: follows `prefers-color-scheme`. The toggle ("Blackboard" / "Paper") sets `data-theme`, which is stored in localStorage behind try/catch.

### Type

- Body: **Literata** (opsz auto) 19px / 1.62 on desktop, 17.5px / 1.6 at ≤640px. Old-style proportional figures in prose, tabular lining figures in code and tables. Measure is 66ch.
- Headings: Literata at weight 620–640 with tight tracking. H1 is `clamp(2.1rem, …, 3.1rem)`, H2 is `clamp(1.9rem, …, 2.45rem)`, H3 is 1.75rem, the dek is 1.375rem.
- UI and labels: **Recursive**, `CASL 1` (casual, upright) for breadcrumb, buttons, captions and the TOC.
- Hand lettering: Recursive `CASL 1, CRSV 1, slnt -3`. Used inside figures and for the two "scribble" labels (key-rule label, Pause-and-think label). Nowhere else.
- Code and identifiers: Recursive `MONO 1, CASL 0`. Code comments use `MONO 1, CASL 1`.
- Scale: −1 = 0.875rem, 0 = 1.1875rem, 1 = 1.375rem, 2 = 1.75rem, 3 = fluid.

### Spacing and grid

- Spacing steps: 4 / 8 / 12 / 16 / 24 / 32 / 48 / 72px (`--s1`…`--s8`).
- The grid has named lines `full | wide | body`. `body` is `min(66ch, 100% − 32px)`. `wide` adds 96px per side, so it is about 920px. There is a 16px gutter at 375px and no horizontal scroll (checked at 375 and 1440).
- Figures, the clip and the table sit on `wide`. Prose, callouts and the code sit on `body`.
- At ≥1420px a sticky left rail shows the section outline with scrollspy. Below that width the TOC is only at the top (collapsed at ≤640px).

## Components (all present in the sample)

1. Sticky top bar: breadcrumb, section progress `§2.4 · n%` with a 2px blue line, theme toggle.
2. Lecture header: kicker, H1, dek, meta (source, last reviewed, error link), full lecture TOC with "you are here".
3. Section head: § number, H2, italic dek, time and class timestamps.
4. Notation key: shown once per lecture, same glyphs as the figures.
5. Key rule: a hand-ruled box (asymmetric radii, 1.6px ink) with a small bottom-up sketch. This echoes the boxed sentence on the board.
6. Static figure: three panels on graph paper, redrawn from the 00:56 board. They stack below 760px.
7. Step-through: a vertical swim-lane figure (time runs down so it fits 375px), Prev/Next, ←/→/Home/End on the focused figure, clickable step list, aria-live narration, and deep links like `#fig-lag/step-3`. Current step is at full colour, past steps at 38%, future steps hidden. Without JS, every step and its text is shown.
8. Pause and think: a flat sticky-note card, not rotated and without shadow. You commit to an answer, then the answer is revealed. Without JS the answer is visible.
9. Sourced fact: a block quote with its source line and link, followed by a paraphrase in the prose ("typically under one second").
10. Clip placeholder: SVG poster (the end state, annotated), play pill with duration, chapter chips, caption, and a status line. The predict prompt sits before the clip.
11. Trade-off table: glyph headers, one red ✕ cell. Below 700px it becomes stacked rows with column labels.
12. Named collapsible asides ("If the master dies", "Why not let replicas take writes too?"). Each has a one-line reason you might skip it.
13. Recall: three questions with `details` reveal.
14. Section end: next-chapter link and the concepts introduced.

## Diagram conventions chosen

- **Stroke:** one 1.7px graphite stroke with round caps. Each segment is a cubic with a bow of at most 1.3px plus about 0.3px jitter. There are no double strokes, no hachure and no rough.js. Shapes are filled with the sheet colour so the grid doesn't show through.
- **Glyphs:** API server is a rectangle with 3px chamfered corners and the name in mono. A fleet is drawn as stacked offset copies with a `×5` label. Database is a cylinder; master is solid, replica is dashed (5/4) and labelled `×N`. Load balancer is a narrow vertical bar. Client is a stick figure, as on the board.
- **Arrows:** solid means a synchronous request and dashed means async (replication). Arrowheads are open two-stroke chevrons and sit on the initiator's direction only. Architecture views use orthogonal routing; diagonals appear only in the time-sequence view.
- **Colour:** blue is the request path, green is an ack or success, red is a failure, a stale read or a hard limit. Graphite is everything else. Colour never encodes the type of box.
- **Labels:** written on the arrows and shapes, never in a legend. Hand lettering is used for annotations, mono for identifiers, SQL and sizes (`16 GB`, `hash(user_id)`). Panel titles sit under the drawing, as on the board.
- **Steps:** circled numerals on the time axis, matched one-to-one with the numbered step text.
- **Speech bubble:** at most one per section, and only for the misconception (the master: "still every write on me?").
- **Accessibility:** every figure has a `<title>` and a `<desc>` that states the mechanism in words.

## Three honest weaknesses

1. **The hand-drawn feel is fragile at scale.** Hand lettering, wobble and graph paper sit very close to the Excalidraw look. Holding the line takes ongoing discipline: tight wobble limits, one stroke weight, and a single generator or glyph library. A lecture with 12 figures will drift unless every figure is built from the same parts. One sloppy figure makes the whole site look childish.
2. **Big, dense figures don't fit the notebook idiom.** It works for 3–7 elements. A 1280×640 poster or a full architecture view shrinks to 6–8px lettering at 375px; the clip poster here already does. Each large figure needs a mobile re-layout, which is a real per-lecture cost. Directions A and C scale down more gracefully.
3. **Three fixed marker colours carry no identity.** Blue, red and green mean path, failure and ack, so there is no colour left to track *which* request, key or shard is which (the samwho device). Prose terms can't be colour-linked to parts the way they can in C. Sharding and consistent-hashing lectures will need hatching or numbering instead. The warm, serif-plus-casual voice also reads as softer than A, which some senior readers may take for less rigour.
