## Rules
- **Own voice.** No teacher–student dialogue, no student names, no "Student 3 asked". Class Q&A insights become
  explanation; a student's proposal is "suggested in class" / "a tempting idea", followed by the teacher's refinement.
  Students' production stories become "From practice" margin notes without names. The instructor's own war stories may
  say "the instructor".
- **Faithful.** The teacher's points stay as taught. Keep hedges as hedges ("in the class's view", "the instructor wasn't
  sure whether…") and opinions as the lecture's view. Never invent history, numbers, mechanisms or motives that are not
  in the ledger/transcript; any outside fact carries an inline `<Cite>` to a page that says it. Do not claim the page
  reorders the class unless it does.
- **Fact-check policy, exactly as `factcheck_applied.md` says:** a `<SourceNote>` ("More precisely") sits directly after
  the teacher's point, which stays (the note never replaces it); inline clarifications are a clause or a sentence with
  a source link; unverifiable items are attributed, not "corrected".
- **Tag everything for coverage.** Every prose block that teaches an item ends with `[[L-0012 L-0013]]`; every component
  that teaches one has `k="L-…"`. Every placed id of your sections must appear, in the section it is placed in.
  Untagged prose is allowed only for transitions and openings that teach nothing new.
- **Exam-proof writing** (lessons from Lecture 1's blind exam): a list the board numbered appears in the board's order;
  the answer to a question sits next to the question (don't split one point across far-apart sections); the teacher's
  caveats and follow-ups stay with the claim they qualify; numbers and conditions are stated exactly as taught.
- **Figures:** use the kit for every diagram (one hand, one stroke family, author at the FIGURES.md scales, labels ≥ 12px
  on screen, a `<Phone>` layout for anything wider than ~360 units). Marker colours: blue request/data path, red
  failure/stale/limit, green ack/success, graphite everything else. Arrowheads on the initiator's side; replication is
  a pull (replica → master). At most one speech bubble per section, only for its misconception. Every figure has
  title + desc stating the mechanism. Unique ids and seeds.
- **Components** as in the outline vocabulary: one RuleBox per chapter, 3 RecallQuestions per chapter, PauseAndThink
  with question-specific `right`/`wrong` verdict text (never templated, never contradicting the reveal), TradeoffTable,
  MarginNote, ForwardChip for deferred topics (with the course lecture number when known), NotationKey once per lecture.
- **Chapters are separate pages:** each chapter opens cleanly (a one-line problem in the lecture's running case) and
  hands off to the next; the Pager handles navigation.
- **Write only the files assigned to you.** Never edit shared files: `site/src/components/`, `site/src/figures/kit/`,
  `site/src/figures/glyphs.tsx`, `site/src/layouts/`, `site/src/lib/`, `site/src/styles/`, `site/src/pages/`,
  `site/src/animations/{lib,registry.ts,Root.tsx}`, `site/scripts/`, `learn/animations-lab/src/lib/`, another lecture's
  folders, or another writer's parts. Other lectures are being built at the same time. If a shared component needs a
  change, write it in your report under "Shared change needed" (the design fixer may make it under the shared lock).

## Machine safety (the laptop crashed once from overload)
Never run `npm`, `npx astro`, `astro dev`, Playwright or `remotion` directly. Use only:
- `pipeline/bin/site.sh build {{LECTURE_ID}} [--parts a,b --tag T]`, `coverage`, `links`, `figures`, `qa`, `posters`, `gates`, `text`
- `pipeline/bin/lab.sh tsc|check|mp4|strip|copy|site-check <clip>`

They take the machine lock `/tmp/vtb-heavy.lock` for every heavy step (build, Playwright, Remotion), wait for it when
another lecture holds it, always release it, and never leave a server or browser running. Remotion renders use
concurrency 1. Prefer one build per round of edits over many builds; a writer builds only its own parts
(`--parts`). If a build fails in a file you do not own, wait a minute and build again; never edit that file.
